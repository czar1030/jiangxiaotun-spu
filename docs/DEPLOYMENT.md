# 发布与密钥保护

GitHub 仓库提供源码下载；要让访客打开网址直接使用，必须另外部署 Node 后端。
GitHub Pages 只能托管静态页面，不能代替本项目的 AI 和语音接口。

## 容器运行

```sh
docker build -t jiangxiaotun-spu .
docker run --rm -p 10000:10000 jiangxiaotun-spu
```

访问 `http://localhost:10000`。默认提供资料直答，不调用付费 AI。
容器已安装语音所需 Python 和固定版本依赖；网络自然语音仍依赖外部语音服务的可达性。

## Render 免费体验部署

使用仓库的 `render.yaml` 创建 Blueprint，或选 Docker Web Service、Free 套餐，健康检查 `/api/health`。
不要在托管平台开通自动升级或付费套餐，除非自己明确需要。
免费服务可能休眠，重新打开时有冷启动等待；平台具体免费额度以其当前页面为准。
项目不依赖当前电脑开机。收藏、偏好和对话仍分别保存于每位访客自己的浏览器。

## 开启在线 AI 前

1. 在 AI 服务商创建仅供本项目使用的独立密钥，限制模型和权限；设置服务商**强制执行的金额/额度上限**，关闭自动充值。余额提示或邮件提醒不能替代硬上限。若该服务商不支持硬上限，保持在线 AI 关闭，或改用支持硬上限的服务商。
2. 只在托管服务的私密环境变量中填写 `AI_API_KEY`，不要写进网页、源码、Dockerfile、构建参数、截图、日志或 GitHub 文件。GitHub Secrets 也不会自动变成外部托管平台的运行环境变量。
3. 服务端配置 `AI_BASE_URL`（HTTPS 服务地址）、`AI_MODEL`、`AI_API_STYLE`。三个参数由服务器固定，浏览器请求不能覆盖。
4. 配置 `AI_USAGE_FILE` 为服务器私有目录的绝对路径，并挂载持久存储。只运行一个应用实例；不能用独立临时磁盘的多副本来声称存在全站统一额度。免费临时磁盘重新部署后可能丢失账本；在这种部署上，服务商硬额度仍是不可缺少的最终限制。
5. 确认以上设置后，设置 `AI_PROVIDER_BUDGET_CONFIRMED=true`、`AI_ENABLED=true` 并重启。未同时配置这两个开关与绝对账本路径时，生产模式不会调用在线 AI。

默认保护：全站每天最多 100 次上游请求、每个连接来源每天最多 20 次、全站每天预留最多 200,000 输出 token、每次最多 12,000 输出 token、输入最多 120,000 字符、最多两个并发上游请求。自然日按 UTC 计算；需要时通过 `.env.example` 中的变量调低。

每次重试和长行程分段都单独扣除上游次数及本次最大输出额度；失败也不退还，以免遗漏已计费请求。预留 token 是保守保护值，并非实际用量或金额统计，输入也会计费。账本损坏、无法写入或正在被另一进程锁定时拒绝在线调用，不静默重置。达到额度后返回明确标注的资料直答。

接口还按连接来源限制提问与语音频率。不信任访客传入的转发 IP；在反向代理后不同访客可能共享限额，这是保守限制。来源检查不是登录认证，公开接口仍可能被脚本调用；要限定参与人员，应在部署入口再加访问登录或平台访问控制。

## 发布检查

```sh
npm test
npm run test:security
```

发布目录不能包含 `.env`、私钥、运行账本、缓存、日志、动画工作文件、Python 虚拟环境或浏览器数据。`.env.example` 仅使用占位内容。若密钥曾公开，即使删除文件仍应立即在服务商撤销换新，因为 Git 历史和缓存可能保留旧值。

原始资料、照片和角色署名及其各自许可保留于 `public/`。本仓库未给第三方资料另行授予新许可。
