# 连续补间与柔性跟随

用户确认帧率以约 60 FPS 为目标，动作流畅和自然优先于固定数字。

此次修改针对三个接待场景的机械感。原挥手曲线已有每秒 60 个采样，问题包含逐格取样、动作打断时目标突变、衣物始终随关节刚性转动；增加一个 FPS 常量并不能解决这些问题。

- 三个场景都按显示时刻在相邻挥手姿势间插值，支持 30／60／120 Hz；保留已确认的动作、面孔及衣物。
- 悬停挥手、点击欢迎与回到原场景之间，使用当前可见姿势作过渡起点。道具先收起，手臂再过渡。
- 躯干、头部、耳朵、呆毛和尾巴使用不同的稳定时间，形成先后跟随。
- 衣袖增加运动驱动的曲线形变；肩部和手腕的坐标始终保持原值。裙摆从腰缝以下跟随，系带轻微滞后；没有添加循环晃动或改变手中道具的定位。
- 重复的 SVG 路径计算和未改变属性的写入有缓存，并跳过软衣袖渲染中原有硬关节的重复更新。
- 旅行地图、放大镜、踮脚望远镜、社区电脑开合、欢迎及休息动作继续使用各自原有动作路线。社区没有恢复打字。

正常界面不显示性能信息。开发检查入口为 `http://127.0.0.1:3210/?motionDebug=1`；需点击左侧板块让角色显示，历史聊天恢复时角色可能被隐藏。右下角统计实际完成的场景渲染，而不是采样数量。帧率依赖设备、窗口状态及其他运行中的程序；不可把 60 Hz 曲线采样声称为任何设备始终至少 30 FPS。

实机窗口中，武汉约 55–58 FPS、旅行约 60 FPS、社区在同时运行离线渲染及测试时约 50 FPS，结束后台检查后复测约 60 FPS、竞技场约 60 FPS。该测量只是本机当前窗口的短时记录。

验证：`npm test` 84／84；包含 30／60／120 Hz 的动作连续性、服装形变边界与不改变握持位置、衣物收势、休息和揉眼动作的安全过渡。

可复查素材在 `qa/motion-fluidity/`。执行 `node scripts/preview_fluid_motion.mjs`，再执行 `python scripts/render_fluid_motion.py` 可从实际生产渲染器导出 198 帧／6.6 秒的 30 FPS 挥手预览。WebP 使用 33／34 毫秒帧时长；GIF 因百分之一秒量化使用 30／40／30 毫秒的重复节奏。它们是现有矢量角色的连续补间渲染，并非新增 198 张手绘角色原画。
